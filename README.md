# PromptFolio

สื่อการสอนการเขียน Prompt ตามหลัก **RTCF** (Role · Task · Context · Format) สำหรับนักเรียนชั้น ม.3
โรงเรียนทีปังกรวิทยาพัฒน์ (วัดสุนทรสถิต) ในพระราชูปถัมภ์ฯ

นักเรียนเรียนหลัก RTCF ผ่านบทเรียนและเกม แล้วฝึกเขียน prompt จริงผ่านภารกิจที่เหมือนเล่นเกม (เก็บดาว ผ่านด่าน R → T → C → F ได้เหรียญ) ได้ prompt ที่ถูกหลัก พร้อมนำไปใช้กับ ChatGPT, Gemini หรือ Claude

**เปิดใช้งาน:** https://thapananthongpak-code.github.io/Project-Pm/

ไม่มี backend ข้อมูลทั้งหมด (คำตอบ ดาว เหรียญ) เก็บใน `localStorage` ของเครื่องผู้ใช้

## ใช้สอนในห้องเรียน

1. **เรียนรู้ RTCF** (เมนูแรก): บทเรียน 11 สไลด์
   - Prompt คืออะไร (เทียบ prompt แย่ vs ดี) → R → T → C → F → รวมร่าง → เคล็ดลับใช้ AI อย่างปลอดภัย
   - **เกมแยก RTCF**: อ่านประโยค แล้วทายว่าเป็น R, T, C หรือ F (10 ข้อ)
   - **เกมเลือกให้ดีกว่า**: เลือก prompt ที่ดีกว่าจาก 2 แบบ พร้อมเหตุผล (4 ข้อ)
   - **โหมดนำเสนอ**: ปุ่มมุมขวาบน เปิดเต็มจอและขยายตัวอักษรตามขนาดจอ ใช้ฉายโปรเจกเตอร์ได้ เปลี่ยนสไลด์ด้วยลูกศร ← → หรือคลิกเกอร์ กด Esc เพื่อออก
2. **สร้าง prompt / สร้างภาพ** (ภารกิจ): นักเรียนตอบคำถามทีละด่าน แต่ละหน้าบอกว่ากำลังเติมส่วนไหนของ RTCF และมีน้องพรอมต์ (มาสคอต) อธิบายว่าทำไม ผลลัพธ์แสดง prompt แยกสีตาม R/T/C/F
3. **ตรวจ prompt**: นักเรียนวาง prompt ที่เขียนเอง ระบบบอกว่ามี R/T/C/F ครบไหม ขาดอะไร และเติมให้เป็นหัวข้อ RTCF

**ระบบเกม:** ดูสไลด์ได้ 5 ดาว ตอบเกมถูกได้ 10 ดาว ตอบคำถามภารกิจครบ 1 หน้าได้ 10 ดาว ภารกิจสำเร็จได้ 50 ดาว (ได้ครั้งเดียวต่อเรื่อง) และมีเหรียญ 6 แบบ ดูได้ที่สไลด์สุดท้ายของบทเรียน
**ห้องคอมที่ใช้เครื่องร่วมกัน:** ให้กด "ล้างดาวและเหรียญ" ที่สไลด์สุดท้าย และ "เริ่มใหม่" ในหน้าผลลัพธ์ ก่อนส่งเครื่องให้คนถัดไป

## วิธีใช้ (สำหรับนักเรียน)

มี 4 เมนู: **เรียนรู้ RTCF**, **สร้าง prompt**, **สร้างภาพ** และ **ตรวจ prompt**

**ภารกิจ**: ตอบคำถามทีละด่าน เรียง R → T → C → F คำตอบบันทึกอัตโนมัติ ปิดเว็บแล้วกลับมาทำต่อได้

1. **เลือกภารกิจ**
   - **พอร์ตโฟลิโอ เข้า ม.4**: R บทบาทของ AI → T แผนการเรียน/โรงเรียนที่จะสมัคร → C เกี่ยวกับฉัน → C จุดเด่นและผลงาน → F หน้าตาสไลด์
   - **สื่อนำเสนองาน**: R บทบาทของ AI → T วิชา (12 วิชา/กิจกรรม หรือ "อื่นๆ" พิมพ์เอง) และหัวข้อ → C ประเด็นที่อยากเล่า → C ผู้นำเสนอ → F หน้าตาสไลด์
   - **สร้างภาพ**: R บทบาทของ AI → T ในภาพมีอะไร → C เอาไปใช้ที่ไหน ใครดู (ระบบเลือกสัดส่วนภาพให้) → F สไตล์การ์ตูน อารมณ์ โทนสี ได้ prompt สร้างภาพ พร้อมปุ่มปรับภาพเพิ่ม (ขอ 4 แบบ / สีสดขึ้น / พื้นหลังขาว / น่ารักขึ้น)
2. **ตอบคำถาม**: ช่องที่มีตัวอย่าง กด "ดูตัวอย่าง" ได้
3. **เลือก AI**: ChatGPT / Gemini / Claude
4. **ได้ prompt** ทำตามทีละขั้นในแชทเดียวกัน
   1. **เขียนเนื้อหา**: กด "คัดลอก แล้วเปิด ChatGPT" (หรือ AI ที่เลือก) ระบบจะคัดลอก prompt และเปิดแชทใหม่ให้ แล้ววางได้เลย
   2. **ทำเป็นสไลด์**: วางต่อในแชทเดิม AI จะนำเนื้อหาที่เพิ่งเขียนมาทำเป็นไฟล์สไลด์ (ChatGPT/Claude ได้ไฟล์ .pptx ส่วน Gemini ทำใน Canvas แล้วส่งออกไป Google Slides)
   3. **สร้างรูปการ์ตูน** (ถ้าอยากได้): เลือกรูป (ตัวการ์ตูนของฉัน / ภาพปกสไลด์ / ไอคอนหัวข้อ) และสไตล์ (ชิบิน่ารัก, อนิเมะ, การ์ตูน 3D, สีน้ำ, ดูเดิล, แฟลตมินิมอล, พิกเซลอาร์ต, สติกเกอร์) เรื่องราวในรูปดึงจากคำตอบที่กรอกไว้แล้ว ไม่ต้องกรอกเพิ่ม
      - ChatGPT และ Gemini สร้างรูปภาพได้โดยตรง
      - Claude สร้างรูปภาพแบบนั้นไม่ได้ prompt จึงขอให้วาดเป็นภาพ SVG แบบเรียบง่ายแทน (เว็บแจ้งผู้ใช้ด้วย)
   - **ปรับเนื้อหาเพิ่ม**: สั้นลง / เปลี่ยนโทน / แปลอังกฤษ / ทีละหน้า

**ตรวจ prompt**: วาง prompt ที่เขียนเอง ระบบตรวจ 8 ข้อแบ่งตาม R (บทบาท) · T (คำกริยาบอกงาน) · C (เราเป็นใคร/ใครดู, จุดประสงค์/ข้อมูล) · F (หน้าตาคำตอบ, โทน, ความยาว) + เคล็ดลับให้ AI ถามกลับ ป้าย R T C F ติดไฟตามที่ตรวจเจอ และเติมส่วนที่ขาดให้เป็นหัวข้อ RTCF

## แก้ไขหรือเพิ่มเนื้อหา

### เพิ่มหรือแก้เทมเพลต

แก้ `src/data/templates.json`

```json
{
  "id": "my-template",
  "title": "ชื่อเทมเพลต",
  "description": "อธิบายสั้นๆ",
  "stage": "content",
  "goals": ["present"],
  "body": "ช่วยเขียน... {{pageCount}} หน้า วิชา{{subjectLabel}}\n- ประเด็น: {{keyPoints}}"
}
```

- `stage`: `content` (ขั้นที่ 1 เขียนเนื้อหา), `design` (ขั้นที่ 2 ทำสไลด์), `image` (ขั้นที่ 3 รูปการ์ตูน) หรือ `refine` (ปรับเนื้อหาเพิ่ม)
- เพิ่มสไตล์การ์ตูนได้ที่ `styles` ใน `images.json` (`label` คือชื่อบนปุ่ม `desc` คือคำที่ใส่ใน prompt)
- `{{fieldId}}` ต้องตรงกับ `id` ของช่องใน `questions.json`
- ค่าพิเศษ: `{{slideSuffix}}` (วิธีส่งออกสไลด์ของ AI ที่เลือก), `{{subjectLabel}}` (วิชาที่เลือก หรือที่พิมพ์เองเมื่อเลือก "อื่นๆ"), `{{deckType}}` `{{photoHint}}` (จาก goals.json), `{{audience}}`, `{{refineMode}}`
- ถ้าไม่เลือกสไตล์หรือโทนสี จะใช้ค่า "เรียบง่าย อ่านง่าย" และ "ที่เข้ากับเนื้อหา"
- ช่องที่ผู้ใช้ไม่ได้ตอบจะแสดงเป็น `[__]` ถ้าเป็นบรรทัดแบบ `หัวข้อ: {{x}}` และช่องนั้นไม่บังคับ ระบบจะตัดบรรทัดทิ้ง
- เป้าหมายหนึ่งควรมีเทมเพลต `content` อย่างน้อย 1 แบบ (ระบบใช้แบบแรกที่ตรงกับเป้าหมาย)

### เพิ่มคำถาม

แก้ `src/data/questions.json` ข้อความ `label`, `title`, `subtitle`, `placeholder`, `example` เป็นข้อความเดียว หรือแยกตามเป้าหมายก็ได้ เช่น

```json
"label": { "default": "ชื่อ-นามสกุล", "present": "ชื่อ หรือ ชื่อกลุ่ม" }
```

- ใส่ `"goals": ["m4"]` ที่หน้าหรือช่อง เพื่อให้แสดงเฉพาะหัวข้อนั้น
- ใส่ `"showIf": { "field": "subject", "equals": "อื่นๆ" }` เพื่อแสดงช่องเมื่อเลือกตัวเลือกนั้น
- เพิ่มรายวิชาได้ที่ `options` ของช่อง `subject`

## การออกแบบ

- เหมือนเล่นเกม: ภารกิจ ด่าน R → T → C → F ดาว เหรียญ มาสคอต พลุกระดาษ และแอนิเมชัน (เด้ง ลอย สั่นเมื่อลืมกรอก สไลด์เลื่อน) ไม่ใช้อิโมจิ ไอคอนและมาสคอตเป็น SVG
- สีประจำ RTCF ใช้เหมือนกันทั้งเว็บ: R ม่วง · T ฟ้า · C ส้ม · F เขียว
- Mobile-first ปุ่มสูงอย่างน้อย 44px ปุ่มย้อนกลับ/ถัดไปติดล่างจอ
- ฟอนต์ Prompt (หัวข้อ) + Noto Sans Thai (เนื้อหา) ขนาดพื้นฐาน 17px
- สีหลักม่วง สีรองฟ้า สีเน้นส้ม บนพื้นขาวนวล การ์ดมุมโค้ง เงานุ่ม
- Dark mode ตามระบบ และสลับเองได้ (จำค่าไว้)
- Accessibility: focus ring สีส้มชัดเจน, ลิงก์ “ข้ามไปเนื้อหาหลัก”, ย้ายโฟกัสไปหัวข้อเมื่อเปลี่ยนขั้น, error ประกาศด้วย `role="alert"`, ปุ่มตัวเลือกใช้ `aria-pressed`, รองรับ `prefers-reduced-motion` (ปิดแอนิเมชันและพลุกระดาษอัตโนมัติ)

## ใช้ได้ทุกอุปกรณ์

- หน้าเว็บขยายเต็มจอตั้งแต่มือถือ แท็บเล็ต จนถึงคอม (กว้างสุด 1280px) การ์ดเรียง 3 คอลัมน์บนจอกว้าง
- ปุ่มย้อนกลับ/ถัดไปติดล่างจอเสมอ
- เปิดแบบเต็มจอเหมือนแอปได้: บนมือถือกด "แชร์ → เพิ่มลงในหน้าจอโฮม" (iPhone/iPad) หรือ "ติดตั้งแอป / เพิ่มลงหน้าจอหลัก" (Android/Chrome) แล้วเปิดจากไอคอน จะไม่มีแถบเบราว์เซอร์

## ใช้พร้อมกันหลายคน

ได้ไม่จำกัด เว็บเป็นไฟล์ static ไม่มีเซิร์ฟเวอร์หรือฐานข้อมูล ทุกอย่างทำงานในเบราว์เซอร์ของแต่ละคน และคำตอบเก็บในเครื่องของแต่ละคน จึงไม่ปนกัน

## Deploy

ทุกครั้งที่ push ขึ้น branch `main` GitHub Actions ([.github/workflows/deploy.yml](.github/workflows/deploy.yml)) จะรันเทสต์ build แล้ว deploy ขึ้น GitHub Pages อัตโนมัติ ใช้เวลาราว 1-2 นาที

ถ้าใช้คอมพิวเตอร์เครื่องเดียวกันต่อกันหลายคน (เช่น ห้องคอม) คำตอบของคนก่อนจะยังอยู่ ให้กด **เริ่มใหม่** ในหน้าผลลัพธ์ก่อนส่งต่อ
